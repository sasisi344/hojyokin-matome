# DeepResearch 設計 — ニッチ補助金リサーチ

防犯グッズ・宅配ボックスの2テーマを**個別セッション**で調査し、結果をフォルダ単位でレポート化する。

## 実行の流れ

1. `prompts/01-bohan-goods.md` を DeepResearch に投入 → `output/bohan-goods/` に成果物
2. `prompts/02-takuhaibox.md` を DeepResearch に投入 → `output/takuhaibox/` に成果物
3. 両レポート完成後、横断比較が必要なら `prompts/03-cross-compare.md`（任意）を実行

**1テーマ = 1セッション。** 混在させない（ソース管理・信頼度ラベルが崩れるため）。

## 出力フォルダ構成（各テーマ共通）

```
output/{テーマ}/
├── 00-executive-summary.md    # 3分で読める結論
├── 01-subsidy-inventory.md    # 制度一覧（公式ソース基準）
├── 02-rarity-analysis.md      # 全国でも珍しいかの判定
├── 03-introduction-timeline.md # 導入時期・拡大の流れ
├── 04-user-voice.md           # 利用者の声（非公式ソース限定）
└── sources/
    ├── official-urls.md         # go.jp / lg.jp 等の公式URL一覧
    ├── secondary-urls.md      # 民間まとめ・報道（参考扱い）
    └── rejected-urls.md       # 採用しなかったURLと理由
```

## 信頼度の階層（全テーマ共通）

| ランク | ドメイン例 | 用途 |
|--------|-----------|------|
| **A（主軸）** | `*.go.jp`, `*.lg.jp`, `city.*.jp`, `pref.*.jp`, `*.or.jp`（公的機関） | 補助内容・金額・期限・要件の**事実** |
| **B（補助）** | `*.co.jp`（メーカー・業界団体・補助金ポータル） | 制度の網羅リスト・申請フロー補足。**Aと矛盾したらAを採用** |
| **C（感想のみ）** | `*.jp` の個人ブログ、掲示板、SNS、`*.com` 等 | **利用者の感想・申請体験**に限定。補助金の事実には使わない |
| **却下** | 出典不明、AI生成っぽいまとめ、古い年度のキャッシュのみ | `sources/rejected-urls.md` に記録 |

### ドメイン判定ルール

- **jpドメインを主体に信頼する。** 海外ドメインは原則却下（報道翻訳記事など例外は理由を明記）。
- `go.jp` / 地方自治体ドメインは「信頼に値するデータ」の**主軸**。
- `co.jp` は企業・業界サイト。制度の**存在確認の補助**には使えるが、金額・期限は必ず公式と突合。
- `.com` / `.net` / 個人ブログは**ユーザー感想セグメントのみ**。

## 調査観点（3本柱）

### 1. 全国でも珍しい補助金か

判定を4段階で付ける：

| 判定 | 基準 |
|------|------|
| **希少** | 全国で10自治体未満、または対象品目が極めて限定的 |
| **やや希少** | 10〜30自治体、または都道府県ごとにバラつきが大きい |
| **一般的** | 30自治体以上、または「住まいの防犯対策」系で広く展開 |
| **定番** | 国の制度＋多数の自治体で標準化（宅配ボックスはこちらに近づきつつ） |

根拠に「確認できた自治体数」「国制度の有無」「類似制度との比較」を必ず添える。

### 2. 導入時期

- 制度の**開始年度**（初回実施年）
- **拡大の転換点**（例：コロナ後、置き配条例、防犯重点施策）
- 現在の年度・受付状況
- 廃止・縮小された自治体があれば記載

公式の「沿革」「過去の実績」ページを優先。なければ `令和○年度版` PDF の年度差分で推定し、**推定であることを明記**。

### 3. 利用者の感想

- 申請のしやすさ（書類・審査期間）
- 実際にもらえた金額 vs 期待
- ハマりどころ（事前申請、領収書要件、賃貸の同意など）
- ネガティブ（不支給、予算終了、手続きの煩雑さ）

**Cランクソースのみ使用。** 公式サイトの「よくある質問」は A 扱いで事実確認に使ってよい。

## 品質チェックリスト（提出前）

- [ ] 補助金の金額・期限はすべて A ソースで裏取りしたか
- [ ] B ソースのみの事実に「要公式確認」ラベルを付けたか

- [ ] 希少性判定に根拠数値があるか
- [ ] 導入時期に「推定」ラベルが必要な箇所に付いているか
